## M2.7 Built for Claude Code

MiniMax engineered the M2.7 model with heavy, explicit focus on capturing the market for Anthropic-native developer tools — most notably **Claude Code**. While M2.7 is technically a massive 230B parameter general Mixture-of-Experts (MoE) foundation model, MiniMax built structural compatibility specifically to hijack Claude Code workflows.

### 1. Native Anthropic-Compatible API

No third-party proxy (like LiteLLM) needed. MiniMax officially hosts a dedicated Anthropic-compatible endpoint:

- `https://api.minimax.io/anthropic` (international)
- `https://api.minimaxi.com/anthropic` (China)

This endpoint natively accepts Anthropic-style payloads, understanding the exact system prompts and dense tool-calling syntax that Claude Code automatically generates.

### 2. Official Claude Code Integration Guides

MiniMax's developer documentation features a dedicated guide for Claude Code. It explicitly instructs developers on how to edit the native Claude Code configuration file (`~/.claude/settings.json`) or VS Code extension settings to swap out the default Claude weights and point directly to MiniMax-M2.7.

### 3. Prompt Caching Solution

Claude Code repeatedly passes your entire git repository and terminal state back to the LLM, making prompt caching mandatory to prevent costs from spiraling. MiniMax anticipated this: M2.7 features **automatic cache optimization**. While baseline input cost is $0.30/M tokens, cached blended cost drops to **$0.06/M tokens** — directly neutralizing the heavy context-repetition penalty of the Claude Code agent loop.

### 4. Tailored for Agentic Loops ("MM Claw")

MiniMax benchmarks M2.7 against an agent evaluation suite called **MM Claw** (scoring 62.7%, encroaching on Claude Sonnet's performance). It was trained specifically to handle agentic harnesses required by terminal-native environments — SRE troubleshooting, reading multi-turn logs, and following strict, complex system rules without hallucinating syntactical tool errors.

### Verdict

This isn't just a clever financial workaround — **it is an officially supported deployment path designed by MiniMax.** Because they built native Anthropic API mapping and ultra-cheap prompt caching directly into the M2.7 pipeline, running 2-3 concurrent Claude Code sessions powered by MiniMax is structurally sound, highly optimized, and vastly more cost-effective than native Anthropic sessions.

## The Real Limits: API Plan Analysis

While the 15,000 requests/5-hour limit on the Max-Highspeed plan (used here) sounds massive, it's functionally unreachable. Here's why:

### The Math: Why 4% Usage is Normal

- 15,000 requests / 5 hours = **3,000 requests/hour** = **50 requests/minute** = ~1 request/second non-stop for 5 hours
- Even 3 concurrent Claude Code sessions can't hit this speed due to natural bottlenecks:
  - M2.7 reasoning takes 5-15 seconds per response
  - Local CLI execution (parsing, running commands, formatting output) takes 2-5 seconds
- Realistic max: 6-12 requests/minute across 3 sessions = ~3,600 requests in 5 hours (24% of the cap)
- Normal usage (reading code, thinking between prompts): ~2 requests/minute → ~600 requests (4% of cap)

### The Actual Bottlenecks (Hidden Ceilings)

**1. Weekly Quota Trap:** "The weekly usage allowance is set at 10× the 5-hour usage quota" = **150,000 requests/week**. This exists to prevent teams from routing a corporate backend through a single $20-100 account. If an agent gets stuck in an infinite loop overnight, it burns through the weekly cap fast.

**2. TPS Splitting (Throughput Nerf):** The plan guarantees ~100 TPS sustained throughput, but this bandwidth is **shared across concurrent sessions**. When 2 sessions simultaneously write large code blocks, the 3rd session drags.

**3. Shared Cluster Congestion (SSE Timeouts):** Even on "High-Speed," you're on shared commercial infrastructure. During peak hours (weekdays 15:00-17:30), MiniMax enforces indirect throttling via SSE timeouts, mid-response interruptions, or high latency — slowing agents organically rather than hard-blocking them.

**4. Hidden Thinking-Block Trap:** M2.7 is a forced-reasoning model. Its benchmark scores rely on internal "thinking" chains. But when routed through Anthropic-compatible endpoints, many proxy/API translation tools inject `thinking: {"type": "disabled"}` to prevent format crashes. This functionally nerfs the model's deep troubleshooting capability.

**5. MoE Context-Prefill Congestion:** If concurrent sessions work on different repos/branches, the backend must compute massive context pre-fills simultaneously. TPS drops sharply as the server swaps expert weights across distinct codebases — unless on the dedicated M2.7-highspeed tier.

### Plan Comparison

| Tier | Concurrent Agents | Requests/5hr | Best For |
|------|-------------------|-------------|----------|
| Starter/Plus | ~1 | 1,500 / 4,500 | Single developer, light coding |
| Max | ~2 | 9,000 | Active developer, 2 sessions |
| Max-Highspeed | 2-3 | 15,000 | Power user, 3 concurrent sessions |
| Ultra | ~4 | 30,000+ | Team/enterprise |

### Final Verdict

The 15,000 number is a psychological "unlimited" trick — an unreachable ceiling for a developer using 3 agents, which is why usage sits comfortably at 4%. The real constraints are:
- **Token-generation speed degradation** during concurrent high-demand moments
- **150,000 weekly cap** if an unattended agent loops indefinitely
- **Thinking-block trap** from Anthropic API format mismatch

For developers running 2-3 concurrent Claude Code sessions via MiniMax, the setup is highly optimized and the advertised limits are effectively irrelevant in practice.
