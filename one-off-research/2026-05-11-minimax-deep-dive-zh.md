## 1. MiniMax 的根本差异

### 计费模型

MiniMax 的 Token 计划按**请求次数**计费，而非按 Token 计费。这是与所有主流厂商的最大区别。

| 厂商 | 计费单位 | Agent 每日成本（10K 调用） |
|---|---|---|
| MiniMax M2.7 | 按请求（每5小时1.5万次） | $0（$80/月套餐已含） |
| Anthropic Claude Opus | 按 Token（$15/$75 百万） | $50-200/天 |
| OpenAI GPT-5.4 | 按 Token（$5/$30 百万） | $20-80/天 |
| DeepSeek V4 Pro | 按 Token（$1.74/$3.48 百万） | $3-10/天 |

每月 300M+ 输入 Token 仅需 $80 固定费用，MiniMax 的实际成本约为 **$0.25/百万 Token** — 比美国前沿厂商便宜 10-100 倍。

### 架构效率

MiniMax M2.7 采用 MoE（混合专家）架构 — 每个 Token 仅激活部分参数。结合激进的提示词缓存，每次 agent 调用的实际计算成本极低。大多数调用实际上是缓存查询，而非完整的模型推理。

## 2. MiniMax 激进缓存的工作原理

### 机制

MiniMax 在其 `/anthropic` 端点支持 Anthropic 原生 `cache_control` 协议。缓存行为：

1. OpenClaw（或 Claude Code）在系统提示词和对话轮次末尾放置 `cache_control` 断点
2. 下次调用时，MiniMax 检查前缀是否匹配已缓存版本
3. 缓存命中 → 以 **0.1 倍成本**读取（90% 折扣），刷新 5 分钟 TTL
4. 缓存未命中 → 完整处理，以 1.25 倍成本写入缓存

### 为什么 Agent 工作负载受益最大

Agent 每次调用都会重新发送相同的 10-20K Token 系统提示词。对话前缀很少改变。5 分钟 TTL 在每次命中时刷新，活跃对话可无限期维持热缓存。

**我们使用中的真实数据（2026 年 4 月）：**
- 输入：3.164 亿 Token（30 天）
- 输出：83.88 万 Token（30 天）
- **压缩比：约 377:1**
- 单请求基准：300 真实输入 → 55,000 缓存 → 125 输出

### 什么会破坏缓存

- **停顿 > 5 分钟** — TTL 过期，下次调用需支付完整 1.25 倍写入成本
- **30 分钟心跳间隔** — 每次都是冷缓存启动
- **非重复前缀** — 每次调用加载新文件/上下文会阻止缓存匹配

### Claude Code 与 OpenClaw Agent 的缓存收益对比

| | Claude Code | OpenClaw Agent |
|---|---|---|
| 每次会话调用次数 | 快速爆发 50-200 次 | 每次交互 1-5 次 |
| 缓存状态 | 始终热缓存（调用间隔 < 5 秒） | 频繁冷缓存 |
| 系统提示词大小 | ~8K（工具 + 规则） | ~15K（SOUL.md 等） |
| 缓存节省成本 | ~75% | ~50%（冷启动命中更少） |

## 3. OpenClaw 集成问题

### Bug #68470 — 提示词缓存重复计数

MiniMax 使用自定义字段报告缓存命中：
```
prompt_cache_hit_tokens: 30000   ← MiniMax 专用
```

OpenClaw 期望 OpenAI 标准格式：
```
input_tokens_details.cached_tokens: 30000   ← OpenAI 标准
```

**故障链：**
1. `normalizeUsage()` 检查 OpenAI 风格的 `cached_tokens` → 未找到 → `usesOpenAIStylePromptTotals = false`
2. `derivePromptTokens()` 求和 `input + cacheRead + cacheWrite` → 重复计数缓存 Token
3. 50K 真实提示词 + 30K 缓存命中 → 被计为 **80K**（50K + 30K）
4. `tokenUsedRatio = 80,000 / 256,000 = 31%` → 在实际上下文仅 20% 时触发压缩

**影响：** 每次会话 16 次不必要的上下文压缩。每 1-2 轮对话就丢失历史记录。记忆刷新过早触发。Agent 因不断丢失上下文而显得更笨。

**临时方案：** 在 compaction 配置中禁用 `memoryFlush.enabled`（不修复底层的 Token 计数问题）。
**修复状态：** PR #68750 于 2026 年 4 月 19 日提出 — 合并状态不明。

### MiniMax 报告格式破坏的工具

任何读取 API 用量数据的工具都会误报 MiniMax 的使用情况：
- OpenClaw 的上下文追踪 — 重复计数
- Claude Code 的 `/stats` — 显示夸大的输入数字
- 第三方 Token 仪表板 — 全部被非标准字段格式破坏

## 4. 中美成本优势对比

### 能源并非主要故事

| 成本构成（每 GPU-小时） | 美国（H100，弗吉尼亚） | 中国（Ascend，深圳） | 中国优势 |
|---|---|---|---|
| GPU 摊销 | $0.64（~$3 万 / 3年） | $0.15（~$7 千 / 3年） | **4.3 倍** |
| 电力 | $0.08（@ $0.09/kWh） | $0.03（@ $0.03/kWh） | 2.7 倍 |
| 冷却与设施 | $0.06 | $0.02 | 3 倍 |
| 运营 | $0.04 | $0.01 | 4 倍 |
| **合计** | **$0.87/小时** | **$0.23/小时** | **3.8 倍** |

能源仅占裸 GPU 成本的约 10%。真正的驱动因素：**NVIDIA 在 H100 上的 $26,700 利润** vs 国内生产的华为昇腾芯片仅 $7K。中国厂商完全避免了 NVIDIA 税。

### 商业模式差距

| | Claude Opus 4.6 | MiniMax M2.7 |
|---|---|---|
| 服务成本（百万 Token） | ~$8 | ~$0.50 |
| 收费价格 | ~$90（$15 输入 + $75 输出） | $0（固定费率套餐） |
| 毛利率 | ~91% | 不适用（VC 补贴） |

美国厂商按奢侈品定价。中国厂商按公共事业定价 — 接近成本，有时甚至低于成本（由 VC 或政府补贴）。MiniMax 的 $80/月 固定费率是市场份额策略：先获取开发者，以后再考虑利润。

### "电力差距"

- 中国发电量是美国的 **2 倍以上**
- 仅 2024 年就新增 543 GW — 超过美国历史总和
- 到 2030 年将有 400 GW 闲置容量 — 是当时全球数据中心预计需求的 3 倍
- 美国未来 3 年面临 44 GW 的电力缺口
- 中国数据中心建设周期以月计，美国以年计（许可审批、电网接入排队）

## 6. 定位关键洞察

1. **以计费模式而非性能作为卖点。** "按请求付费，而非按 Token" 对 Agent 工作负载是最有力的差异化优势。相同用量下，MiniMax 比替代方案便宜 10-100 倍。

2. **缓存故事是双刃剑。** 377:1 的压缩比令人印象深刻，但仅适用于具有重复系统提示词的 Agent 工作负载。对于一次性 API 调用，优势大幅缩小。

3. **工具问题是真实且未解决的。** 所有监控工具都因 MiniMax 的自定义报告格式而失效。这给需要成本可视化的开发者带来摩擦。

4. **中国成本优势是结构性的，而非暂时的。** 硬件成本差距（国产 GPU vs NVIDIA）、能源盈余、以及建设速度不会消失。这不是促销 — 这是基准线。

5. **DeepSeek 是更危险的竞争对手。** DeepSeek V4 Pro 提供按 Token 计费、OpenAI 兼容 API、99% 缓存折扣 — 实际上比 MiniMax 的 90% 更激进。MiniMax 唯一拥有而 DeepSeek 没有的是按请求计费。
