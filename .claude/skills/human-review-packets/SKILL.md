# Human review packets

Turn an existing static review packet into a self-contained local HTML review application without changing the source packet or its evidence. This is also the mandatory layout for classifier evaluations shown in a browser.

## Mandatory browser layout

Every owner-review or classifier-evaluation page opened for the owner must use the deterministic builder below. Do not create a one-off vertical report, card stack, alternate tab system, or separate comparison layout.

The enforced layout has:

- one post per outer numbered tab;
- one inner tab per eligible brand review;
- source evidence in the independently scrollable left pane;
- taxonomy controls and any classifier result in the independently scrollable right pane;
- post-level fields below the per-brand section;
- `white-space: pre-wrap` plus `overflow-wrap: anywhere` for source and model text;
- the `pushinweight-tabbed-review-v1` layout marker generated by the builder.

Stored English translations must mirror the source post's visible structure as closely as the evidence permits. Preserve paragraph breaks, blank lines, headings, list/number markers, standalone dates, handles, URLs, thread markers, and hashtag lines. Never collapse a multiline source into one translation paragraph merely because the stored translation arrived flattened. If the persisted translation already retains its structure, render it verbatim with `class="stored-translation" data-source-format="preserved"`. If it is flattened, project only source-visible structural boundaries into the same translation text, without rewriting words, and mark it `data-source-format="projected"`. Include `data-source-lines` with the source post's line count so validation can reject a projected multiline translation that remains a single block.

For a classifier evaluation, pass `--model-results`. The builder renders model answers in red above the blank owner controls without treating model output as an owner judgment. The model-results file must cover the same ordered cases and eligible brands as the packet; unknown fields or mismatched cases/brands fail the build.

When the active taxonomy contains Geopolitical mode `nationalism`, the packet must enforce its country-axis dependency. Selecting a directional China or U.S. national stance (`mild_pro`, `pro`, `constructive_critical`, `anti`, or `mixed`) automatically selects `nationalism`. Removing `nationalism` or selecting an exclusive non-geopolitical/unavailable mode resets directional country stances to `none`. This prevents a review export from carrying nation-directed sentiment without its required mode; `unknown` remains available for genuinely unavailable context.

## Before building

1. Read the repository instructions, `fix-ui`, and `avoiding-recurring-mistakes`.
2. Identify the authoritative taxonomy source named by the user. For the AI-enrichment work, read the latest requirements in the existing canonical plan; do not create or edit a parallel plan.
3. Compare that source with [references/latest-taxonomy.json](references/latest-taxonomy.json). Update the JSON only when the authoritative contract has actually changed.
4. Require evidence-backed brand membership. A `posts_brands` association alone does not prove a `PostBrandSignal`. Use an export that identifies nonempty signals for each `(post, brand)` pair.

The packet's designated target brand always receives a review tab. Add other stored brands only when the signal export proves that pair has at least one `PostBrandSignal`. Keep association-only brands visible in source metadata.

## Build

Use the deterministic builder:

```bash
ruby .claude/skills/human-review-packets/scripts/build_tabbed_review.rb \
  --source-html /path/to/source-packet.html \
  --review-inputs /path/to/frozen-review-inputs.json \
  --signals-csv /path/to/candidate-export.csv \
  --model-results /path/to/model-results.json \
  --output-html /tmp/review-packet-tabbed.html
```

Omit `--model-results` only for a blank owner-review packet.

Repeat `--signals-csv` when signal evidence spans multiple exports. The CSV must contain `tweet_id`, `brand_id`, and `existing_signals`; a blank `existing_signals` value does not create a signal-backed tab.

The builder preserves source text and context, creates one outer tab per post, creates inner tabs for the eligible brand reviews, keeps Untracked Brand Promotions once per post, and embeds local autosave plus JSON export. It fails loudly on missing cases, duplicate case IDs, mismatched article counts, missing target brands, or absent signal evidence.

Validate every generated page before opening it:

```bash
ruby .claude/skills/human-review-packets/scripts/validate_tabbed_review.rb \
  --html /tmp/review-packet-tabbed.html \
  --cases 5 \
  --require-model-results
```

The optional model-results JSON has this shape:

```json
{
  "model_label": "DeepSeek V4 Flash 0731",
  "cases": {
    "N01": {
      "per_brand": {"deepseek": {"outcome": "classified"}},
      "post_level": {"untracked_brand_promotions": ["none"], "promoted_subjects": []}
    }
  }
}
```

Per-brand and post-level keys must exist in the selected taxonomy. `promoted_subjects` is the only additional post-level display field.

## Verify

Drive the generated file in a real Chromium browser before delivery:

- exactly one post panel is visible;
- the desktop viewport shows independently scrollable left evidence and right review panes with no page-level horizontal overflow;
- every expected signal-backed brand tab exists and association-only brands do not acquire tabs;
- changing a brand or post saves first, and selections survive both navigation and reload;
- `other`, explicit `none`, `unavailable`, and post-level `general` obey their exclusivity rules;
- progress markers update and the downloaded JSON preserves separate `per_brand` and `post_level` answers;
- browser errors and console errors are empty.
- `[data-layout-contract="pushinweight-tabbed-review-v1"]` exists exactly once;
- classifier pages contain `[data-model-results="true"]` and at least one `[data-model-result]` per eligible brand plus one post-level result per case;
- all outer and inner tab/panel counts match, and no vertically stacked multi-post fallback is present.
- every rendered stored translation declares `data-source-format="preserved|projected"`; when `data-source-lines` is greater than one, its rendered text contains line breaks rather than one collapsed text block.

Preserve the original file. Save the generated file under a new name. Copy or open it on another machine only when the user explicitly requests that external write or GUI action.

## Boundaries

This skill does not authorize database writes, provider calls, classifier changes, commits, deployment, or edits to an actively owned plan. Browser `localStorage` is the durable working copy; the JSON download is the portable backup.
