Historical inspiration and intent

The family takes its character from the physical presence of a Qin quan: a compact cast weight whose authority comes from mass, proportion, and an object made by hand. The system does not copy inscriptions or ask a user to understand historical Chinese writing. With the narrow exception of the intentionally recognizable 京 locale symbol, meaning comes from familiar contemporary silhouettes.

The historical influence enters through form: shoulders are slightly uneven, circles are not mechanically perfect, baselines drift, paired sides do not mirror exactly, and terminals feel blunt and rounded. These controlled irregularities suggest cast and worked material without adding corrosion, texture filters, decorative cracks, or imitation calligraphy.

The goal is useful recognition at phone size first, then distinctive character on a second look. A heart must still read as a heart; a reply bubble as a reply; a hammer in a working hand as hands-on use. Cyber-Quan succeeds when the user understands the signal before noticing the historical reference.

What the icon system achieves

  • Replaced the public dashboard's emoji and generic glyph vocabulary with one coherent 33-symbol SVG runtime family.
  • Kept icon geometry separate from application presentation: every production symbol inherits currentColor, while the surrounding state owns any semantic tone.
  • Created redundant at-a-glance magnitude cues for followers: one through four human figures, progressively larger display, a luminance progression, and the exact follower count together.
  • Made trend direction explicit with blunt solid triangles: point-up for rising and point-down for falling.
  • Made operational post types pictorial and literal: a working hand with a Qin-era hammer, comparison bars, a question bubble, a separated emitter and waves, a dated event card, and a hand-held announcer.
  • Integrated the same semantic symbols in feed rows and matching filter options instead of maintaining separate emoji and SVG vocabularies.
  • Established one locked company mark, compact locale/place symbols, four time-of-day symbols, and shared control/score symbols.
  • Made runtime symbol selection fail closed: unknown or data-derived IDs do not render.

Form and extension grammar

  • Universal silhouette first. Sketch the simplest recognizable object or action before adding Cyber-Quan character. Do not make Chinese-script knowledge a prerequisite.
  • Controlled irregularity. Use small asymmetries, off-axis balance, bowed horizontals, uneven shoulders, and non-identical repeated elements. The object should feel worked, not broken.
  • Roughness in geometry. Build character into paths and proportions. Do not use noise, texture masks, faux corrosion, distress filters, or random wobble.
  • Blunt, humane strokes. Prefer rounded line caps and joins for open strokes. Stroke weight usually sits near the current family's compact range; verify optical weight rather than copying one number blindly.
  • Small-size clarity. Judge at the production placement, not only in a large artboard. Keep major negative spaces open and avoid interior detail that closes at approximately 10–15 px.
  • Redundant direction and magnitude. When a signal expresses order, movement, or scale, let silhouette reinforce the text rather than replace it.
  • Family resemblance, not cloning. Reuse the stroke temperament and proportion logic. Do not repeat the weight silhouette inside every icon or force unrelated objects into the same outline.
  • No embedded application state. Geometry uses currentColor. Selected, sentiment, role, magnitude, and warning presentation remain owned by the parent UI.

Composition patterns already established

  • Shared outer form, changed interior: the four sentiment faces reuse one slightly irregular face contour; positive, negative, and mixed change the mouth/eye expression, while neutral deliberately omits the mouth.
  • Progressive population: follower magnitude grows from one to four human forms while preserving the count as the precise value.
  • Shared symbol, changed contextual meaning: one credential-badge geometry represents official, staff, and community; label and parent presentation distinguish the roles.
  • Paired directional forms: rise and fall use slightly irregular solid triangles pointing in opposite directions; flat remains a gently irregular horizontal.
  • Related environmental set: sunrise, day, dusk, and night share a sky/daypart vocabulary but remain individually recognizable.

Runtime and accessibility contract

  • Keep each symbol on viewBox="0 0 24 24". Preserve the symbol ID when refining existing geometry; changing an ID is an application migration, not an art-only edit.
  • Use stroke="currentColor" and/or fill="currentColor". Do not hard-code UI colors in the symbol.
  • Add runtime symbols to both the inline sprite allowlist and pw-icons.js. Add a semantic mapping only when the symbol is selected from a controlled application key.
  • Never construct a fragment ID directly from feed, API, or user data. The renderer must continue to return an empty string for unknown symbols and sanitize CSS class names.
  • Decorative SVG instances remain aria-hidden="true" and focusable="false". The containing control, text label, or semantic wrapper owns the accessible name and state.
  • Follower magnitude and account role are separate semantics: each has its own label-bearing wrapper. An absent role retains its reserved visual slot without exposing a meaningless accessible object.
  • Server-rendered rows and asynchronous feed/chart refreshes must resolve to the same symbol, order, presentation class, and accessible label.
  • Do not enlarge production controls to accommodate a new drawing. Refine the geometry until it resolves within the established placement.
  • Render place/character forms as paths, not font-dependent <text>, so shape and metrics remain stable across devices.

Continuation checklist for future agents

  1. Confirm the signal has a stable, user-facing meaning and that an icon materially improves scanning.
  2. Start from first principles and familiar iconography; do not start from an emoji or a historical character.
  3. Draw in 0 0 24 24 with clear negative space and currentColor.
  4. Apply controlled unevenness only after the silhouette reads instantly.
  5. Review beside related production symbols at both large specimen size and the actual UI size.
  6. Check narrow-phone, desktop, English, Simplified Chinese, server-rendered, and asynchronous paths.
  7. Add the exact geometry to the production sprite and the constant-only allowlist; never accept data-derived fragment IDs.
  8. Add or update semantic mapping only where a stable application key selects the icon.
  9. Keep the SVG decorative and place the localized accessible name on its text/control wrapper.
  10. Update the icon contract to assert exact inventory, nonempty geometry, common viewBox, fail-closed rendering, and real browser geometry.
  11. Verify that replacing or adding an icon does not alter control geometry, overflow, content order, or unrelated interactions.
  12. Record a new owner decision before replacing a locked symbol or extending the system into a new semantic category.

Current regression boundary

The production contract asserts an exact 33-symbol runtime inventory, unique IDs, a shared viewBox, nonempty shape geometry, a constant-only fail-closed renderer, approved runtime/source relationships, semantic follower and sentiment behavior, and real browser rendering across desktop and narrow phone widths. Any extension should strengthen that same boundary rather than create a parallel icon registry.
