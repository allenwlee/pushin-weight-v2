## PI-U11 local API contract

`read_status()`, `request_state(state, *, expected_revision, actor, reason)` and `acknowledge(revision, *, boundary)` return one versioned snapshot. Optional `directory=` supports an explicitly selected local store for tests or a configured owner. `PulseControlUnavailable`, `PulseControlConflict` and input validation distinguish operational, concurrent and malformed requests. No configured store means unavailable, not running/stopped. Initial creation requires explicit initialization; a missing file cannot silently recreate running state.

Snapshot fields: `schema_version`, `status`, `desired_state`, `desired_revision`, `acknowledged_state`, `acknowledged_revision`, `requested_at`, `requested_by`, `reason`, `acknowledged_at`, `boundary`, `observed_at`, `error`, `diagnostics`, `discarded_diagnostics`. Status is running/stopped only for the current acknowledged revision; otherwise stop_requested/resume_requested. All local timestamps use JST. All unknown fields and wrong types are rejected. Concurrent stale requests/acknowledgements fail; duplicate acknowledgement is idempotent. Atomic writes preserve the previous valid state on a failed replace. Diagnostics are bounded and retention loss is counted. Only owner-triggered state requests change desired processing state; errors do not initiate semantic repair or request a stop.

Local file transport is testable now; cross-service durability/transport is an unresolved production prerequisite. P3 may copy the finished module unchanged for local page integration, while P1 retains ownership. API reads and unavailable handling are safe without a store.
