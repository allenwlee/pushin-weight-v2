# Goal

Restore the production post-fetch pipeline so the literal latest 50 persisted
posts reliably contain a Simplified Chinese rendering whenever the detected
language is not `zh-Hans`, plus genuine English and Simplified Chinese analyst
commentary for every post. A translation stage may be marked succeeded only
when its persisted output satisfies that contract. The fix must preserve the
existing fetch, attribution, classification, feed, headline, and deployment
behavior outside this enrichment contract.

## Product Contract

### Evidence and problem statement

The production cron was halted before implementation under the repository's
live-anomaly rule. A read-only aggregate query against the paused production
database on 2026-08-27 found:

- 5,026 translation-pending and 4,927 classification-pending enrichment rows;
- 66,710 translation-failed and 64,143 classification-failed rows;
- in the literal latest 50 posts, 30 translation/classification stages were
  pending;
- the other 20 were marked translation-succeeded even though the newly
  required `commentary_en` field was empty;
- `commentary_zh_cn` coverage was 20/50 and `commentary_en` coverage was 0/50;
- all 20 posts in that cohort with `lang_detected != 'zh-Hans'` did have
  `text_zh_cn`, so that translation dimension must not regress while the
  commentary gap is fixed.

The code-review evidence identifies four contributing defects:

1. `CycleRunner._run_post_fetch` treats a row as translated when it merely has
   a detected language, regardless of missing translation/commentary output.
2. The translator explicitly permits `cn_equivalent: N/A`, and the persistence
   layer converts that value to `NULL`.
3. No English commentary is requested or persisted; the older approved UI
   contract intentionally deferred it, but the owner has now explicitly
   superseded that deferral.
4. The 90-second enrichment budget is only an admission check; nested retries,
   network calls, and classifier per-post fallback can run past it.

### Actors and flows

1. **Feed reader:** receives a persisted source post, Chinese rendering, and
   bilingual analyst synthesis without waiting indefinitely or seeing a
   translation stage falsely reported as complete.
2. **Harvester operator:** can distinguish complete, pending, and failed
   enrichment; can measure the requested latest-50 acceptance rates with the
   read-only health checker; and can verify no unrelated checker dimension
   regressed relative to the retained cohort baseline.
3. **Harvester cycle:** claims a bounded freshest-first batch, calls only the
   stages still pending for each row, persists validated outputs, and leaves an
   incomplete row retryable instead of recording false success.

### Requirements

- **R1.** The translator response contract requires a non-empty canonical
  `lang_detected`, non-empty Chinese analyst commentary, and non-empty English
  analyst commentary for every non-empty persisted post. `N/A`, `NA`, blank,
  missing, and non-string commentary values are incomplete outputs.
- **R2.** `text_zh_cn` is required whenever `lang_detected != 'zh-Hans'`.
  Existing source-serves behavior for Simplified Chinese remains valid and the
  persisted column may mirror source text for that language.
- **R3.** `text_en` continues to satisfy the existing source-serves contract:
  English source may mirror source text at persistence, while non-English
  source receives an English rendering. This avoids weakening the existing
  checker while implementing the new criteria.
- **R4.** The English commentary is an LLM-authored English-language analyst
  synthesis analogous to `cn_equivalent`; it must not be filled by copying the
  source or either translation. Emoji-only posts receive a concise bilingual
  interpretation rather than an empty sentinel.
- **R5.** An incomplete first-pass translator row gets at most one targeted
  full-row repair request. A still-incomplete row is returned as
  `translation_failed` and remains pending for a later cycle under existing
  attempt/age limits.
- **R6.** Translation succeeds only after the exact values to be persisted
  satisfy R1-R4. A valid language alone is never sufficient.
- **R7.** Recently created false-success translation states whose persisted
  output violates R1-R4 are deterministically returned to pending. Reconciliation
  is limited by the existing enrichment age window; it does not reopen the
  entire historical corpus or alter classification success.
- **R8.** Translation and classification calls are built from their own pending
  subsets. Repairing translation-only debt does not spend a classifier call or
  replace existing classification rows.
- **R9.** Each provider attempt receives a bounded socket timeout and all
  translator retries, classifier retries, per-post fallbacks, and sleeps obey
  one enrichment-attempt monotonic deadline. Deadline exhaustion leaves
  unresolved stages pending and releases their lease.
- **R10.** The claim size and bounded attempt budget are large enough to admit
  and process the literal latest 50 in one healthy production cycle while
  preserving the 13-minute cycle-wide deadline and two-minute next-slot
  reserve. The settled values for this recovery are `claim_per_cycle: 50`,
  `request_timeout_seconds: 45`, and `attempt_budget_seconds: 300`; the shared
  attempt deadline, not a multiplied retry count, is the hard upper bound.
- **R11.** The health checker exposes numerator, denominator, percentage, and
  pass/fail for all three owner-defined rates. It keeps all existing
  persistence/classification checks so unrelated regressions remain visible.
- **R12.** The checker remains read-only, bounded, credential-safe, and capable
  of producing the existing detailed evidence report with source text,
  persisted outputs, reconstructed verbatim current-code prompts/request
  kwargs, and script provenance.
- **R13.** No fetch query, TwitterAPI cadence/credit behavior, model name,
  provider route, attribution, classifier taxonomy, discourse persistence,
  headline worker, schema, feed interaction, or locale presentation changes
  are introduced.

### Key technical decisions

1. **Extend the existing translator row instead of adding another LLM call.**
   Add a required `en_equivalent` alongside the existing `cn_equivalent` in the
   same structured response. This preserves one normal translator request per
   batch and gives both commentary fields common retry/validation semantics.
2. **Validate twice at the correct boundaries.** The translator validates the
   model response before returning it; `CycleRunner` validates the final
   source-fallback-adjusted persistence values before declaring success. This
   prevents helper correctness from masking a persistence-path defect.
3. **Reconcile only recent false successes.** A bounded ORM update reopens
   incomplete succeeded translation states inside `max_age_hours`. It preserves
   attempts and classification state, so current latest-feed debt drains without
   turning 66k historical failures into live work.
4. **Use stage-specific pending subsets.** A claimed state can have one stage
   succeeded and the other pending. Each LLM receives only tweets whose own
   stage is pending; this makes targeted recovery affordable and avoids
   classification regressions.
5. **Make the attempt budget executable.** Thread a small deadline protocol into
   translator and classifier retry helpers. Provider request timeouts are the
   lesser of configured per-request timeout and remaining enrichment budget;
   the classifier does not start per-post fallbacks after expiration. Keep the
   existing three outer attempts, remove the translator SDK's hidden inner
   retries so there is one retry owner, and cap any backoff sleep to remaining
   budget. The production values are a 45-second request ceiling inside one
   300-second attempt deadline.
6. **Measure acceptance separately from legacy health.** Preserve the existing
   `regression_gate` and reason model, and add an explicit owner-defined
   `acceptance_gate` with rate details. A pre-existing secondary discourse miss
   can remain visible without being mislabeled as a regression introduced by
   this fix.
