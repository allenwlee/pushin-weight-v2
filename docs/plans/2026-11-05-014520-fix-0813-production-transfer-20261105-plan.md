## Plain-English Summary

**End state.** Production holds the same 216 daily 0813 measurements (Hugging Face
downloads/likes/trending, Arena rating/rank/votes, OpenRouter tokens for
Aug 13 – Sep 10, 2026) that were reviewed in the backfill database. They are attached
to the 0813 product, so the chart code can read them, and each one still points back
to the exact source capture it came from. Days with no source evidence stay empty,
never zero.

**What changes.** One new management command and one transfer module, built on the
existing shared metric writer. A small, behavior-preserving extraction lets the
existing backfill cohort setup and the production transfer build the contract from
the same code. In production the transfer adds one measurement contract and its
four source mappings, one taxonomy version and measurement subject, 45 replayed
capture runs with their evidence documents, and the 216 values. It also records the
reviewed `llm-model` type on this one product, which the contract requires. No new
tables or columns, no provider calls, no scheduling (`scheduling_enabled` stays
false), and no change to harvesting, other contracts, or Chatter staging.

**Approach.** Copying rows between databases would carry over IDs that don't match
production's. Instead, the reviewed source captures (about 140 KB) are exported once
from the backfill database into a hashed bundle file. A production one-off job then
replays them through the normal writer. The whole transfer runs inside one database
transaction and commits only if every value matches the backfill original field by
field, and the production chart reader returns the same observed points.

**Verification.** Automated tests against the shared test database (export → replay →
compare, tampering, conflicts, idempotency, rollback). A rehearsal run in production
that rolls back by design. Then the real run, followed by read-only production queries
and a reader check.

**Owner attention.** Delivery route (direct to production versus waiting for the
occupied staging branch) is the one open choice; see Delivery.

## Design decisions

- **Storage (M19).** Reuse existing entities only: `MetricCollectionContract`, `SourceSubjectMapping`, `TaxonomyVersion`/`MeasurementSubject`, `CollectionJob`/`CollectionRun`/`CollectionScopeRun` (direct `persist_source` jobs), `CollectionObservation`, `MetricValue`, `CollectionEvidenceArchive`. **0 tables or columns added or retired.** No JSON column added; provenance rides in the existing source-metadata evidence document.
- **Replay, not row copy.** IDs differ across databases (e.g., `metrics.id` hf downloads v2: backfill 47, production 33). Natural keys resolve locally; definitions are compared by `definition_snapshot` minus `id`.
- **Shared code (M7).** Extract `cohort_collection_spec(...)` from `_configure_cohort` so the backfill cohort and the production transfer build the identical reviewed spec. Existing backfill behavior unchanged (regression test).
- **Product type.** Production product `20d66250…` has `product_type_id` NULL; `prepare_collection` requires `llm-model`. The backfill review recorded `local_product_type_review: llm-model` in the contract methodology. The transfer sets it only when NULL and refuses any other existing type. No production taxonomy snapshot contains the product (verified 0), so no frozen contract breaks.
- **Use policy.** The writer runs with normal enforcement (no isolated-review bypass); production `data_sources.metadata.use_policy` grants collection/retention for hf (incl. `cfahlgren1/hub-stats`), arena, openrouter, opencode.
- **Retained production origins.** For the 17 captures that came from production runs, the transfer re-reads the production origin archive, re-applies `select_retained_payload` and requires equality with the bundled payload.
- **Execution host.** Render one-off job from the deployed `pushinweight-harvest` revision (runbook `docs/deploy/render.md`), never the live web service. One transaction; rehearsal = same code with forced rollback.
- **Bundle.** `docs/analysis/2026-11-05-*-0813-transfer-bundle.json`, created read-only from the backfill DB; canonical JSON with `bundle_sha256` over its content; payload hashes re-verified on load.
