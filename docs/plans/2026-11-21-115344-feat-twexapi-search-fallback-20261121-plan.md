## Plain-English Summary

When the primary X search provider fails repeatedly, the harvester should switch to TwexAPI and periodically check whether the primary provider has recovered. This applies only to search: account and other API calls keep their existing provider. An absent fallback key preserves current behavior.

The switch must survive separate scheduled runs, avoid mixing provider pagination cursors, preserve unfinished search windows, and record which provider handled each request. A bounded historical search command will be prepared but not run. Verification uses local tests, a few owner-approved TwexAPI probes, and production reads only. Stop at an open PR; deployment, the Render secret, and the paid plan remain Allen’s choice.

## Problem Frame

Since approximately 13:00 JST, primary advanced search has returned 503s, unexpected empty pages and timeouts, reducing ingestion. Slow per-request retries compound lost coverage. User-supplied probes show TwexAPI paginated search supports the deployed inline time operators. A search fallback must preserve the existing harvester’s normalizing, paging, coverage and cursor invariants.

## Requirements

- R1: Route search only through a configurable shared circuit breaker; preserve the exact primary behavior when `TWEXAPI_API_KEY` is absent. Auth failures are not treated as transient provider outages.
- R2: Persist consecutive failures, state, open-until and half-open probe ownership across cron processes; make thresholds/timeouts configurable and prevent concurrent probe/rate-limit races. Primary success closes the breaker; 5xx, timeout and evidence-backed suspicious empty windows count. Fail safely if state storage is unavailable.
- R3: Map the real TwexAPI envelope and snake-case fields, nested quotes/retweets, authors, UTC times, and metrics into the existing normalized contract. Preserve source raw data and distinguish provider in existing telemetry.
- R4: Do not transfer pagination cursors between providers. On a provider transition restart the exact bounded window or preserve an incomplete prefix and replay the window; idempotent writes prevent duplicates. Never certify an empty page or partial fetch as complete merely because a provider failed.
- R5: A bounded operator-invoked historical search path reuses existing run_backfill acquisition, upsert, and coverage mechanisms; offer preview and explicit execution, forced TwexAPI, JST-aware exact bounds, rate/price guards, and no enrichment/LLM calls. Do not execute it now.
- R6: Local test coverage plus a small set of explicitly authorized live TwexAPI probes spaced at least six seconds; no other paid LLM calls, no production writes or schema application, no merge/deploy.

## Technical Decisions

The default Django caches in `project/settings.py` are process-local/file-local and cannot survive separate Render cron processes. `core.models.CallState` stores a per-query watermark, not a global provider-health decision; `CollectionRun` is an immutable execution record, not an atomic mutable breaker. Add one small typed `SearchProviderCircuit` table and one migration; zero tables retired. Each row denotes one provider/credential-purpose circuit and owns its failure count, open deadline and probe lease. Use atomic transactions and short bounded leases; do not hold DB locks over HTTP. Use database time or injected clock in tests. No JSON fields are added. At runtime this state must be written to the application DB; this task does not write or migrate production.

Count empty success only on an explicitly identified expected-nonempty search (for example, a bounded probe with a demonstrated positive or a continuation claiming further pages); ordinary empty searches are valid and must not trip the breaker. Never send a TwexAPI cursor to TwitterAPI or the reverse. An ambiguous empty must not advance a coverage cursor. Rate-limit physical TwexAPI starts across processes (trial minimum six seconds configurable) with a durable reservation; 429 honors Retry-After within the cycle deadline, with bounded attempts and no retry storm. The provider fallback is feature-gated by the secret; absent key bypasses all state and timing changes, including primary retry defaults.

Official API contract: [TwexAPI OpenAPI](https://twexapi.io/openapi.json), `/twitter/advanced_search/page`, `AdvancedSearchCursorQuery`, `AdvancedSearchCursorResponse`, and `TweetModel`. The advertised page size is up to 20. Treat plan-dependent rate and price as configuration/owner decisions, not hardcoded current facts.

The forced path sets the model-call limit to zero. This switch is not authorization to run a backfill now.

## Risks and Verification

Search providers may implement operators, list searches, cursor direction and field semantics differently; verify exact deployed query shapes and do not assume successful requests prove coverage parity. A trial limit of one call every five seconds makes an 18-query cycle and deep pagination materially slower; exercise time budgets and never increase the schedule or silently declare skipped windows complete. No fallback credential must remain a strict no-op. Store secrets only in process memory; never save authorization headers. Tests use an isolated local database, no production writes, no new paid LLM calls, no production backfill, and no Render changes.
