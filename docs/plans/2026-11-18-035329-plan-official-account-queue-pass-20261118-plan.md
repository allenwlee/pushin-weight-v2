## Planning Contract

### Key technical decisions

- KTD1. Persist a versioned, immutable manifest and append-safe local progress receipts in an operator-owned durable location on the authoritative host, with atomic writes, restrictive permissions, a checksum and a unique run ID. Do not use the 2,000-member historical `OfficialCompanyScan` cursor or add database tables. Existing state and attempt rows remain authoritative; receipts support resumption and audit rather than override them. Reconcile attempts after every crash, including a crash between database commit and receipt write.
- KTD2. Iterate frozen IDs, never invoke `drain --evaluate-only` expecting `--account-id` to filter it. Build a narrow command that calls the existing evaluator under its existing independent lock, with lock held for at most one call; release between calls and yield across natural scheduler windows. Add pacing and bounded contention backoff. Define measurable guardrails against live harvest and scheduled-discovery baseline at execution; stop on breach rather than claiming zero contention by design.
- KTD3. Preserve the existing shared daily and per-cycle conservative budget checks. Use a distinct recorded scope for each real, bounded batch, with a separate durable, concurrency-safe run-wide ceiling covering actual spend plus outstanding reservations across all batch scopes; reject dispatch when that ceiling is reached. Persist scope identity and counters across restarts and reconcile uncertain calls before advancing. Never change shared limits or count a reserve as actual spend. Inspect effective configuration and current provider pricing, and set an explicitly authorized total before execution. A cap reached leaves remaining IDs pending.
- KTD4. Match attempts by state ID and snapshot evidence hash. Include the attempt linked to an active claim at cutoff even if it was created earlier; for other attempts require creation at or after cutoff. Inspect state and immutable receipts together. A subsequent concurrent completed matching attempt may satisfy a member. An old result alone does not prove this pass. Classify changed evidence or settled/suppressed states as such; avoid re-evaluating them under stale evidence. If identity/hash can change between check and claim, close that race inside the existing transactional claim boundary and test the actual caller.
- KTD5. Staging tests use isolated services, synthetic rows, deterministic fake responses and an independent database connection for concurrency. A production provider success cannot be inferred from staging fakes. Any real staging smoke needs a separate, bounded provider credential and authorization.
