# Ollija Guidance Cleanup - Plan

## Plain-English Summary

When this is done, PushinWeight's delivery rules live in one place: the "Plans and delivery" section of `AGENTS.md`, which every Claude and Codex session already reads. That section gains your new standing rule: if production is approved but the shared staging branch is busy with someone else's release, go straight to production instead of waiting or asking. The block Ollija writes into every plan shrinks to the facts that differ per plan (branch, worktree, route, and Ollija's own delivery steps) plus a pointer to those rules. Today that block repeats about 20 lines of policy in every plan.

Separately, the Ollija tool itself gets back in sync. Its home checkout is updated to the released version, the plain-English README intro edit from September 8 is published, the command is reinstalled from that checkout (the way `AGENTS.md` says), and the leftover fix worktree is removed.

Nothing in the app changes and nothing deploys. The changes are documentation, the Ollija template, and the tests that pin that wording. Two other Ollija docs that repeated the delivery rules become pointers, and the Ollija change ledger gets an entry.

Completion is checked by the Ollija test suite in PushinWeight, a regenerated guide in this plan, the reinstalled command reporting the right source and flags, and both repositories' remote `main` branches containing the commits. One difference from "push straight to main": Ollija's GitHub `main` is protected and rejects direct pushes, so its README commit goes through a pull request that merges itself as soon as CI passes. After this lands, an open plan in another session will report "stale guide" once; rerunning `ollija annotate-plan <plan>` fixes it.

- **Stop conditions:**
  - Ollija's pull request CI fails.
  - The README rebase conflicts.
  - A pinned test property cannot be preserved at its new home.
  - The merged Ollija worktree is dirty or locked.
- **Who finishes:** LFG. `ce-work` implements, then review and shipping follow. The Ollija pull request auto-merges; PushinWeight fast-forwards `main` directly.

## Planning Contract

### Key Technical Decisions

- KTD1. **Change only PushinWeight's template; keep Ollija code unchanged.** `render_delivery_guide` substitutes a fixed value map with `string.Template`, so unused values are harmless. `src/ollija/config.py` validates only that the template file exists. Removing placeholders therefore needs no engine change. Governs R4, R5.
- KTD2. **Land the Ollija README through a squash auto-merge pull request.** `main` requires a pull request, the checks `test (3.11)`–`test (3.14)` and `build`, strict status, linear history and enforced admins. It needs zero approving reviews and allows auto-merge and squash only. This is the how-level instance of the push-to-`main` decision and inherits its label. Covers R2, R9. (session-settled: user-approved — chosen over opening a pull request, the LFG default: the owner's explicit request and scope confirmation; the conflict call-out on that Key Decision applies)
- KTD3. **Preserve the README edit by committing it on a new branch and rebasing, not by stashing.** The fast-forward to d324846 also edits `README.md`, at line 224 against the edit's lines 1–8, so Git refuses it while the file is dirty. Committing the edit on a branch cut from the current `HEAD`, then rebasing onto `origin/main`, keeps the edit in history and avoids the shared stash. Governs R1, R2.
- KTD4. **Move the wording pins to the new owner rather than deleting them.** `test_production_worktree_cleanup_contract_remains_in_consumer_policy` pins worktree-retention text in the template. `test_lfg_and_goal_delivery_contract_is_shared_with_current_guidance` requires `docs/operations/ollija.md` to restate the LFG/goal contract. Both checks keep their property, that consumer policy carries the contract, by pinning `AGENTS.md` and requiring the other documents to link to it. Governs R6, R8.
- KTD5. **Mark PushinWeight commits `[skip render]` and record the waived deployment check under Delivery Exceptions.** Docs-only commits on `main` already use this convention, for example 43070ba6 and 317d79d6. Governs R9.
