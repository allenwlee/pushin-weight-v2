## Interpretation

- The three-call arm required 66 deterministic adapter operations: 65 empty arrays were mapped to explicit no-label sentinels and one outer JSON fence was removed.
- The parser recorded 71 events because it also reported five empty `post_types` arrays that were already valid for `context_missing`; those five were not output violations and were left unchanged.
- Every expected slot was returned. There were no invalid enum values, missing decisions, retries, or LLM repairs.
- Isolating post types improved exact post-type agreement from 19.6% to 26.1% and precision from 57.3% to 72.2%.
- Audience-topic agreement fell from 46.2% to 34.6%, leaving overall agreement at 69.4% versus 70.6% for the two-call 0731 run.
- The third call increased measured cost by 33%, from $0.003933 to $0.005246 for 40 posts, while concurrent wall time fell from 40.2 to 31.4 seconds.
- The three-call architecture therefore validates the post-type isolation idea but does not yet beat the two-call configuration overall. The next adjustment belongs inside the audience-topic prompt; reasoning and provider should remain fixed while that is measured.
- No retries, LLM repairs, fallback providers, database writes, or production changes occurred.
- Owner blanks remain excluded. This enriched challenge set is not a live production-accuracy estimate.
