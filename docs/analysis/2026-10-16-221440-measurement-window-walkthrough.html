The database fills the range from the two timestamps

Both midnight boundaries known: PostgreSQL records the full UTC day as [start, next-day midnight). The start is included; the next midnight is excluded. Existing endpoints remain stored.

Status: deployed and verified in production at SHA afa67c817b55f4694993d689b9db3572f130c8eb (PR56), with migrations0091/0092. All six production services were observed LIVE; 397,755 pre-cutover values are unchanged and there are zero range mismatches.

Zero tables added. Zero retired. One existing table changed: metric_values. One generated column and one partial GiST index added. All identities and sample numbers below are fictional.

One existing numeric record, three representations of its window

The migration fills window_range for existing rows. It does not insert replacement metric values. Future inserts and endpoint updates compute the range automatically in the same database statement.

One boundary unknown means the entire range is NULL

An in-progress daily total can retain its known start while its end stays unknown. PostgreSQL keeps the generated range NULL. It never inserts next-day midnight, infinity, fetch time or epoch as a substitute.

State measurements, such as a repo's running likes total, keep their existing as_of_at/as_of_date semantics. They do not acquire a daily interval merely because we poll once per day. Collection time belongs to the observation and is distinct from effective measurement time.

What happens during this release

  1. Migration 0091 obtains the existing metric table lock with a 5-second admission limit and 120-second statement limit.
  2. PostgreSQL computes the generated field for every old row from its own retained timestamps. Both endpoints must be finite and ordered.
  3. Migration 0092 builds the partial GiST index concurrently for non-NULL ranges.
  4. Existing collectors keep writing source evidence and numeric values. The database computes complete ranges or NULL.

Unknown, infinite, zero-length and reversed intervals are distinct: unknown produces NULL; supplied infinity or invalid complete order is rejected.
