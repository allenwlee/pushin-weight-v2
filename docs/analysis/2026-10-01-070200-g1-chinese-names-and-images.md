## October 1 follow-up — broken preview and X account images

At the owner's follow-up, the preview was unreachable: the ce-prototype helper
had stopped after 30 minutes without requests. Its saved state explicitly says
`session_end_reason: idle`; the original URL returned `ERR_CONNECTION_REFUSED`
in Chrome and HTTP checks. All 83 saved photo files were still intact. Lazy
image loading explains why an already-open page can show earlier images while
later ones fail after the server exits.

Replaced that helper with a detached Python static server at the same private
URL, without an idle timer or dependency on the agent process. It remains a
local process and does not restart automatically after a machine reboot. The
viewer now opens the saved image file. Attribution still links to the original
publisher. A bounded direct-image URL audit found 82/83 original images still
responded as images and one `oss.zhidx.com` URL returned HTTP 403; the saved
copy of that image remains available. Source-page availability was not audited.
A second browser reproduction found a cached old JavaScript file after normal
reload. Versioning its URL and returning `Cache-Control: no-store` for editable
HTML/JavaScript/data resolved the stale view.

The owner also requested X account profile images, whether or not they show the
account owner. A read-only production query matched all 40 accounts and found
83 image observations across `accounts.profile_picture`,
`account_profile_snapshots.profile_image_url`, and `posts.author_profile_picture`.

usable images, each 225–400 pixels square, and saved them locally with the
