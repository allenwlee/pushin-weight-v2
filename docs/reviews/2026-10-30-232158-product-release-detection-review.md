# Product-release detection handoff review

Reviewed in this session against the working tree based on `a13fc27b`. This is an in-context code review, not an independent reviewer or a staging receipt. It covers the new per-Post detector handoff and its integration with the existing harvester and release worker; the earlier release-intake review remains separate.

- **Durability:** When the feature is enabled, the Post and its detector request share a transaction. A failed request rolls the Post back and increments the harvester failure count. Repeated and enriched Posts reuse the same queue row.
- **Concurrency and cost:** The worker uses a nonblocking advisory lock per Post, and a newer request remains pending when processing an older generation. Writes have bounded lock and statement waits. A local 100-Post rollback-only timing sample showed extra overhead; it is not a production capacity test.
- **Retry and accounting:** Detection attempts stop at three, retaining the last failure. A lost broker wake-up leaves the request durable. A later batch failure reports prior committed batches and remaining failed IDs. Harvester insert and attribution counts now advance only after their transaction succeeds.
- **Schema and refresh:** The typed one-to-one processing table has a different purpose and lifecycle from source evidence, collection jobs and post enrichment. No JSON field is added. The staging refresh policy excludes environment-local processing state and includes the existing claim-to-collection-job links. Migration reversal refuses to discard populated queue state.
- **Verification:** The latest targeted local PostgreSQL set passed 105 tests, including rollback, concurrent ownership, later-generation requeue, timeout restoration, broker loss and partial-batch failure. The earlier release/study suite passed 192 tests and 12 subtests before the final harvester accounting change. The shared test database was restored to migration 0206 after checking for rows that would be lost. These checks make no provider calls.
- **Existing failure:** The separate harvest lookback test expects at most one hour while unchanged `config.yaml` uses 24 hours. Its dependent check was skipped in the expanded run. This was not fixed or counted as passed.
- **Measurement follow-up:** Saved exact captures without a reviewed Product-specific mapping now retain a waiting scope and recheck it without provider calls. Local tests cover later authority, native-only to Product-specific projection, source timestamps, repeat reuse, exclusion and correction. Native and Product measurements remain distinct partitions of the same captured observation. Structured teacher/parent Product links require separate identity and provenance verification. A real historical 404-to-200 receipt has not been established for the GLM example.
- **Pending delivery evidence:** The first production read-only health observation had 20 fresh pending Posts, an inconclusive regression gate and a failed acceptance gate. The exact cohort must be rechecked after 30 minutes. Staging migration/deployment, finite real-case verification, current PR/CI and the local review report remain outstanding.
